# M7 冻结 test 检索消融报告

## 1. 范围与结论

本报告只评测冻结 `test` 集上的 A～E 纯检索配置，不调用 LLM。全部参数在
`m7_test_protocol.md` 中预先冻结，运行中未根据 test 结果改参。

结论：D（Dense + Reranker）取得最高 Recall@10、MRR@10 和 nDCG@10；E
（Hybrid/RRF + Reranker）也通过相对 A 的检索效果门禁，但 CPU P95 延迟约为
A 的 120 倍，远超 2.5 倍预算。C 未在 test 上复现 dev 增益。应用默认检索继续
使用 Dense；D/E 仅保留为离线研究配置，不接入交互路径。

## 4. 分组观察

- A 在 fact 上 Recall@10 为 0.75，但 comparison 和 cross-document 只有 0.27
  和 0.19；跨文档召回仍是主要瓶颈。
- D 的主要增益来自 fact：Recall/MRR/nDCG 为 0.85/0.75/0.72。它在
  cross-document 上的 nDCG 为 0.18，反而低于 A 的 0.20。
- E 的 comparison Recall 从 A 的 0.27 提升到 0.29，但 cross-document Recall
  从 0.19 降到 0.16，说明当前融合加重排不能稳定解决跨论文证据覆盖。
- 8 道中文可回答题上，D 的 Recall/MRR/nDCG 为 0.51/0.55/0.43，均高于 A 的
  0.39/0.35/0.25；Reranker 对跨语言事实定位有明显帮助。
- BM25 单独使用在所有题型和语言上都低于 Dense，继续只作为 Hybrid 候选分支。

## 5. 门禁判断

完整配置 E 相对 A：

| 门禁 | 结果 | 判断 |
|---|---|---|
| nDCG@10 相对提升至少 5% | +28.75% | 通过 |
| Recall@10 不下降超过 2 pp | +3.54 pp | 通过 |
| MRR@10 不下降超过 2 pp | +9.80 pp | 通过 |
| 全文件命中率不低于 A | 0.725 vs 0.700 | 通过 |
| P95 不超过 A 的 2.5 倍 | 12.6863 s vs 0.1057 s，约 120× | **失败** |
| 引用与拒答门禁 | 等待 A/C/E 端到端生成 | 待定 |

依据预先定义的规则，即使效果达标，只要性能预算失败也不能默认上线。C 虽满足
交互延迟，但 Recall 和 nDCG 低于 A，因此也不作为默认降级替代。当前默认 Dense
保持不变；如果未来具备 GPU，可重新评估 D/E 延迟，但不得用本次 test 继续调参。

## 7. 计时限制

为遵守“冻结 test 只执行一次”的约束，本阶段没有为了延迟统计重复运行完整 test
三次；P50/P95 来自一次冻结运行中的 50 个逐题样本。模型加载不计入逐题延迟，
但没有额外执行 5 道未计分预热题。该限制不影响排序指标和超过两个数量级的性能
门禁结论，不能把本数据用于跨硬件比较。
